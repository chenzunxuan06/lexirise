# 词跃 LexiRise · 方案深化与完整评估（2026-09-04）

> 适用范围：面向大众学生的背单词网站（沪教牛津 1535 词 / Next.js 14 / SQLite / PWA）
> 输入：① 13 项反馈清单 ② 首页 demo（已认可）③ 方案乙（情感驱动 + 图鉴收集，已认可）
> 依据：`web/docs/gamification-design.md`、`词跃LexiRise-v2升级总结`、代码实测（含 `public/words.json` 覆盖统计）

# 一、13 项逐条评估

## 1. 技术栈：不落后，不急于升级；先补"工程债"，后谈"新技术"

**结论：当前栈面向大众 C 端推广完全够用，升级不是优先项。**

| 维度 | 现状（实测） | 评估 |
| --- | --- | --- |
| 框架 | Next.js 14.2.35 App Router + React 18 | 主流一代，社区/生态稳定，**无需升 Next 15**（无收益且有迁移成本） |
| 数据库 | `lib/db.js` 双后端适配：本地 SQLite（Node 22 `node:sqlite` 零依赖 / better-sqlite3 兜底）+ Turso libSQL（可部署 Vercel） | 设计得当；大众化推广后量级仍够（SQLite 单机十万级用户没问题），**现阶段不换 Postgres**，留了 Turso 云端出口 |
| 数据分发 | 词库静态 `public/words.json`（1535 词 31KB 级），客户端直取 | 快、省流量、可 PWA 离线；缺点：改词需重新构建 → 内容管理放后台后建议改为 `/api/words` 读库+静态缓存 |
| PWA | 已配置（manifest + 缓存 + 离线） | 这是大众化最强的点：**"加到主屏幕即 App"**，务必保留并强化（下版本补安装引导） |
| 工程债 | 无 TypeScript；`globals.css` 单文件约 2900 行；无组件库；无测试 | 这才是"显得不高级"的根源 |

**可执行建议（按优先级）：**
1. **不迁移、不换框架**；移动端优先完善 PWA（安装横幅、离线壳、启动屏）。
2. **渐进式 TypeScript**：新文件/新组件用 TS，老文件迁一改一（不要求一步到位）。
3. **样式体系化**：CSS 变量已存在但使用混乱（散装色号遍布），先立 token 清单再逐步收敛（见第 13 项）。
4. 为"微信生态"留后路但不做：若未来要小程序，用 **uni-app/Taro 重写一个壳**（数据接口完全复用现有 API），Web 端不动。
5. 大众化警惕点：注册放开后要限流（防机器人注册刷数据）、`user.db` 备份自动化（已有手动备份，建议 cron 每日快照）。

## 2. 首页导航：目标 = 手机首屏只露 3 块

**结论：首页和侧边栏的"决策点过多"是同一个病根——每个功能都想上首页。**

**具体方案（保留强化 / 收敛折叠）：**

| 保留并强化（首屏） | 收敛或折叠 |
| --- | --- |
| **主按钮「开始今天的学习」**——唯一最大视觉，字号/渐变/呼吸感强化；余量>0 时显示"还剩 N 词"，完成时变成"巩固一轮" | 快捷 2×3 入口格：**删除**，6 个入口全部收敛进侧边栏 |
| **每日任务卡（三件事 + 宝箱进度）**——合并现有"三件事卡"与"宝箱卡"为一张卡：三行任务 + 顶部 0/3 进度 + 全完成时卡内直接变宝箱按钮（不再单独一块） | 「每日一词」：从独立区块改为 hero 下一行小胶囊（点击展开大卡片+朗读），或并入任务卡底部 |
| **宠物 + 等级区（hero）**——宠物、Lv/称号/XP、连击、图鉴小进度条并成一行 hero；图鉴进度做成 hero 右下角小徽章（"图鉴 312/1535"可点击） | 年级进度条保留但降到 hero 次行（仅选过年级时出现） |
| 三件事每一件的目标页**保持不变**（复习/错词/新词） | footer 的备案信息等系统信息收进侧边栏底部 |

**首屏最终结构（手机 375px）：** ①宠物问候 hero（一屏 25%）→ ②"开始今天的学习"主按钮卡（25%）→ ③每日任务卡（40%）→ ④（可滚动）每日一词胶囊 + 图鉴入口。**决策点从 ~12 个降到 3 个。**

## 3. 词表入口：删除合理，但"删入口不删能力"

**结论：同意删除。** 理由成立：词库内容由管理员维护、学生只在"查词/收藏"时用，属于低频工具，不该占决策位。

**但要保证 5 件事不丢：**
1. `/vocab` 页面保留直链，入口改挂两处：训练/复习的**答后反馈卡片"查看详情"**、词库详情页自身（收藏 ☆、例句、AI 讲解都在这里）。
2. 「生词本 ⭐」在复习页有 Tab（favs 数据独立），查词收藏流程不受影响——验证并保留。
3. 侧边栏"词库/短语/词根词缀"**三合一**为「词料库」一个入口（页内 Tab 切换），侧边栏一次减 2 项（见第 13 项）。
4. 内容管理移交后台：admin 增加"词条管理"（编辑词条、今日一词轮换、例句/音标审核补录）。
5. `/mywords`（我的词表）维持现状：直链保留、不进导航，预留家长/老师端。

## 4. 训练页默认化：方向已落地，补三处体验闭环

**结论：v2 已实现"今日模式一键直达"，方案正确，继续深化：**

1. **打开即练**：`/train?mode=daily` 已默认；建议首页主按钮与侧边栏"训练"都指向它，训练页不再有"先选设置"的心理门槛（自定义筛选收进折叠区，已做）。
2. **完成页闭环**：完成后显示"本轮错词一键重练"（现在只有统计），加"明天预告：预计复习 N 词"。
3. **训练节奏感**：答对/答错的窗口内反馈强化（绿/红 + 宠物表情跟随），错题 10 分钟后再到期已有机制，训练中插一句"这个错词稍后还会考你"。

**结论：骨架（XP/金币/宠物/宝箱/combo/徽章）已对，缺的是"频率感"和"盼头"。** 参考主流小程序/App 逐条落地：

| 机制（主流产品在用的） | 落地到本项目 |
| --- | --- |
| **每日首答激励**（多邻国/百词斩首任务高亮） | 每天第一轮学习的每个词 XP×2（"今日首轮加成"角标），激励打开 App 的首个动作 |
| **连击里程碑可视化**（多邻国连击火焰） | 已有 combo 提示，加"连续学习 N 天"火焰进度条（首页 hero 已有 🔥 数字，强化为可点开的日历条） |
| **随机惊喜宝箱**（王者/原神类拆包） | 已实现；把结果反馈升级为"开箱动画 + 三选一保底碎片展示"，碎片进度可见（"还差 2 张合成皮肤"） |
| **收集图鉴**（宝可梦/集卡 App） | 方案乙认可，本期重点做完整（见第四部分专章） |
| **兑换商城** | 金币出口：皮肤/装扮/补签卡/道具（数据已就绪，补 UI 即可） |

| **目标冲刺**（轻量、不攀比） | 个人周目标（如"本周 80 词"）完成发周徽章 + 周报里展示；**不做全服榜，保留好友/同年级小范围周榜（P2）** |

**防沉迷红线不变**：每日 XP 200 / 金币 60 软上限已有；新增"连续学习 25 分钟提醒休息"（家长好感度）。

## 6. 家长查看端：方向可行，优先级后移——现状已够用

**结论：同意后移。** 已上线的最小闭环（周报只读链接：学习天数/新词/复习/正确率/测验/柱状图 + 404 保护）满足"家长零门槛查看"。

**后移理由与触发条件：** 学生侧规模 < 500 活跃用户前，家长端边际价值低；**当活跃用户过 500 或出现首批付费/学校合作意向时再投入**，届时做：周报海报化（统计数据可视化生成图片）、家长可订阅每周自动推送（若做微信/邮件）、可选"每日时长限制"开关。

## 7. 错词重练：保留并强化穿插

**结论：机制已实现（连对 2 次消灭 + 今日模式强制 ≥1/3 错词），强化三个点：**

1. **即时二战**：训练/测验完成页加"本轮 N 个错词，立即重练"按钮（进入错词-only 循环）。
2. **错词到期节奏**：答错后 10 分钟再到期（已有），在今日模式文案里体现"稍后还会见它"——制造"消灭它"的期待感。
3. **消灭仪式感**：消灭动画升级（现在是小 toast），做成"错词卡碎裂"小动画 + 计数（"已消灭 47 个错词"放在成就页/图鉴关联）。

## 8. 管理后台：从"看数字"到"看业务"的指标体系

**结论：现状（用户管理/备份/14 天访问/7 天功能分布）是"运维台"，缺"运营台"。** 分四层建设：

| 层级 | 指标 | 落地方式 |
| --- | --- | --- |
| **增长** | 注册量/日活(DAU)/周活(WAU)/注册→次留 | 现有 events 表 + 新增 `register`、`day_active` 事件（打点扩展，见下） |
| **漏斗** | 新手引导完成率、引导→首轮训练、首轮→次日回归 | Onboarding 各步埋点（step1~5）+ 现有 train_done 串联 |
| **内容** | 单元错题热区（哪个 unit 错题最多）、词条错误率 TOP50、图鉴点亮率 | 现有 events/train 数据可聚合：`meta.unit` 需随 train_done 上报补上 unit 字段 |
| **经济（游戏化风控）** | XP/金币日产出总量、宝箱开箱率、徽章解锁分布、每日任务完成率 | `game` 字段随同步入库，后台定时聚合即可（`user_data.game` 全量可算） |
| **AI 成本** | 每日调用量/用户、缓存命中率、费用估算 | `ai_usage` 表已存在（user_id/date/calls），加一页"AI 用量"即可 |

**事件扩展清单（现有 8 类 → 14 类）：** 现有 `page_view / train_start / train_done / exam_done / chest_open / pet_evolve / badge_earned / share_created`，新增 `register / onboard_step / album_view / pet_interact / ai_ask / day_active`。后台 UI 建议：概览（今日/7日/30日关键指标卡）+ 趋势图（已有）+ 漏斗图 + 内容热区表 + AI 用量页。

## 9. AI 模块：DeepSeek 额度担忧 → 三层解法（现状已是低耗模式）

**结论：你的成本担忧已被"离线预生成"大幅化解，再补三层就基本无忧。**

**现状（实测）：** `lib/ai.js` 走 OpenAI 兼容接口，`LLM_BASE_URL / LLM_MODEL / LLM_API_KEY` 全是环境变量——**换任何 OpenAI 兼容服务商只改 env，零代码改动**；`ai_cache` 表 + `pregen-ai.mjs` 离线预生成 1535 词讲解，线上运行时命中缓存≈零调用。

| 层级 | 方案 | 成本/收益 |
| --- | --- | --- |
| ① 先用起来 | 后台加"AI 用量"页（读 `ai_usage`）+ 每用户每日调用配额（如 30 次/日，超出走规则兜底） | 立刻止血，防个别用户刷爆 |
| ② 换低价/免费模型 | 国产 OpenAI 兼容服务：**智谱 GLM-4-Flash（免费档）→ 阿里通义 qwen-turbo（≈1~2 元/百万 token）→ 硅基流动 SiliconFlow 聚合（多模型按需切）**。只需改环境变量 + 压测一遍 prompt 兼容性 | 成本直接降 10~50 倍，个人额度可用很久 |
| ③ 长期/私有化 | 教师/学校场景：**Ollama 本地部署 7B/14B 模型**（家用机/教室主机即可跑，0 成本 0 泄露），作为"AI 免费版"卖点；云端主站始终预生成优先 | 推广话术+合规双赢 |

**隐私红线（面向未成年）**：prompt 里严禁带用户名/手机号，仅传单词与题目上下文；选服务商时确认数据不用于训练（GLM/通义企业版条款通常可接受，DeepSeek 亦然）。

## 10. 短语的音标：删；例句：留

**结论：同意。** 影响面很小，执行三步：
1. 数据层：跑脚本把短语类词条（`entry_type='phrase'`）的 `phonetic` 置空（或渲染端过滤），一次性更新 `words.json`。
2. 渲染端：`/phrases` 及任意短语卡片不再渲染音标位（音标位留空会撑版式，改为无音标即不显示）。
3. 例句保留且复用：短语例句同时进图鉴卡面/短语卡/AI 讲解素材。

## 11. 内容完整度：硬缺口清单（words.json 实测）

**结论：主干完整（1535 词全词义+分级+单元结构），但"展示型字段"缺口明显，直接影响图鉴/卡面观感：**

| 字段 | 覆盖 | 缺口 | 影响 |
| --- | --- | --- | --- |
| 中英例句 | **568 / 1535（37%）** | 缺 967 | 卡面/训练填词题素材不足 |
| 音标 | 1140 / 1535 | **缺 395（26%）** | 卡面/图鉴无音标、发音兜底变多 |
| 词性 pos | 1148 / 1535 | 缺 387 | 卡面释义略单薄 |
| 词根词缀提示 | **285 / 1535（18%）** | 缺 1250 | 图鉴"词根"栏大面积空白 |
| 简义 with_simple | 0 | — | 设计已决定不做短语音标/简义，符合 |

**补齐路线（成本从低到高，与 AI 降本配合）：**
1. **音标 395 个**：脚本从公开词库（如 ECDICT/有道开放接口）批量补齐 → 半天。
2. **词性 387 个**：同二维数据补 → 与音标同批。
3. **例句 967 条**：AI 预生成（复用 `pregen-ai.mjs` 方案，每词 1 组中英短句，1535 全量覆盖）→ 约 1 天生成 + 人工抽查。
4. **词根提示 1250 条**：AI 预生成（带词根拆解模板，保准确率需加"人工抽查+高危词表跳过"）→ 二期。
> 注：图鉴卡面设计上要给"缺字段"兜底（无词根 → 显示联想记忆法；无例句 → 显示固定搭配短语），不能留白块。

## 12. 新手指引：确认为重要优化点，已在位，再强化三处

**结论：v2 已实现 5 步引导（选年级→领养命名→3 题真实验→记忆曲线讲解→完成页），方向正确。**

强化：
1. **第一天三节点**：引导完成后"今天第一天"特写——首次升级 + 首次宝箱 + 首个徽章（把「首答双倍」机制也给新用户，第一天体验拉满）。
2. **可重看**：设置页放"重新观看引导"；跳过但当天未学任一任务时，下次打开在 hero 提示一次（不打扰墙）。
3. **埋点漏斗**：5 步各打 `onboard_step` 事件，后台看流失在哪一步（现只埋完成）。

## 13. UI 观感：先立规矩再逐页做减法（侧边栏 11 → 8 / 移动端底部 Tab）

**结论："丑"和"乱"的根因不是美术，是没有设计系统**：单文件 2900 行 CSS、图标全 emoji、字号 10.5~30 无阶梯、每个区块自带一套配色。

**统一规矩（先做这 4 件事，观感立刻上一个台阶）：**
1. **色彩叙事**：主绿=学习（现有 `--primary`）/ 金橙=奖励与宝箱 / 蓝紫=AI 与外部链接 / 灰=中性。所有散装色号（`#e9f9ef`、`#5b7fff`、`#ffb84d`…）归位成 token，全站禁新色。
2. **图标系统**：内联 SVG 线性图标组件（1.5px 圆头，24 网格），替换全部 emoji 导航图标；emoji 只留文案彩蛋。
3. **字号阶梯**：11/12/13.5/15/18/22/28 七级，标题 700、正文 400、数字 800，消灭 10.5px 微字。
4. **组件样板**：卡片（16px 圆角/1px 边/统一阴影/悬浮抬升）、按钮三态、Toast 已统一、空状态插图。

**侧边栏收敛（两套方案，推荐 A）：**

> 方案 A（推荐）：**8 项分组**——学习组：首页 / 训练 / 复习 / 单元测验；收获组：成就（等级·图鉴·徽章合一） / AI 学习 / 统计；工具组：**词料库**（词库+短语+词根词缀三合一 Tab）。共 8 项，视觉上组间留 8px 分隔+组标题小字。
> 方案 B（激进）：**6 项**——首页 / 训练 / 复习 / 测验 / 成就 / 词料库；AI 学习与统计移到首页底部"更多"抽屉（游戏大厅风格，见方向 C）。

**移动端（学生主力场景）**：侧边栏抽屉改为**底部 Tab 栏**（首页 / 训练 / 复习 / 成就）+ 右上角"更多"抽屉收纳其余——这是"大众 App 感"的最大来源，建议本期必做。

# 二、demo 提升空间：方案乙框架内 10 个新想法（每条含玩法+情感点）

# 三、方案一（首页简约化）三个大众审美方向

> 共同底线：首屏 3 决策点、主按钮唯一、三件事卡+宝箱合一、每日一词折叠、快捷格删除。

## 方向 A · 清爽卡片风（推荐，成本最低，最接近现状）
- **特征**：白底 + 大圆角卡片（16px）+ 轻阴影 + 两色系统（绿/金橙）；hero 上是宠物+问候一行；三张任务卡垂直排布，每张"图标+文案+进度"。
- **适合**：稳妥升级，学生和家长都接受度高；开发量小（CSS 重构为主）。
- **动效**：卡片进场轻滑入、任务完成打勾弹跳、宝箱按钮呼吸光晕。
- **成本**：≈ 2 天（含侧边栏收敛 + 移动端底部 Tab）。

## 方向 B · 暖萌宠物风（情感驱动最大化）
- **特征**：首页 hero 变成"跃跃的房间"——宠物居中占首屏 40%，背景是浅奶油色+手绘元素（云朵、单词气球）；主按钮做成"带跃跃去学习"的门牌卡片；任务卡做成"今日菜单"样式。
- **适合**：学生情感浓度最高、真正突出"为了跃跃回来"的目标；需要把 PetMascot 升级为高质量 SVG（圆润轮廓+眨眼/漂浮动画）。
- **风险**：家长观感偏幼，评测"科技感"略弱；PetMascot 质量决定成败。
- **成本**：≈ 3~4 天（宠物 SVG 升级是大头）。

## 方向 C · 游戏大厅风（任务化最重）
- **特征**：首页即"每日任务大厅"：顶部宠物+等级条，中部一张"今日任务清单卡"（三件事=三个关卡入口，完成盖印章），底部横向滚动的"本周图鉴挑战/商店上新"卡片位；侧边栏可激进收敛到 6 项（方案 B）。
- **适合**：想突出"游戏"属性的最强选项；对初中生新鲜感高。
- **风险**：和信息架构改动联动大（训练/复习入口语义变成"任务"）；开发成本与回归测试量最高。
- **成本**：≈ 4~5 天（含侧边栏激进收敛 + 任务卡引擎）。

> **建议执行路径**：先做 A（1 期上线，稳定大众观感），B 的宠物升级作为 2 期的独立里程碑（可与图鉴系统同批），C 若要激进改造放最后评估增量价值。

# 四、游戏化完整实现方案（方案乙 · 深化版）

## 4.1 总循环（一条线串起来）

```
打开 App（跃跃问候/想念剧情）
   └→ 每日首答双倍 → 今日任务卡（复习/错词/新词 3 件事）
        ├→ 每件事完成：+15XP/+5币 + 打勾动画（已完成）
        ├→ 三件全成：宝箱（金币/碎片/补签卡/限定徽章，碎片保底）
        ├→ 连对 combo 3/5/10 → 彩带+额外 XP（已完成）
        └→ 训练中错词 → 10 分钟后再考 → 消灭动画（+10XP）
   └→ 图鉴：熟练度 lv≥3 点亮 / ≥7 金边；集齐一套 +100币+纪念徽章；每 50 张=跃跃新动作
   └→ 宠物：饥饿/心情/形态/装扮；进化仪式（Lv5/Lv12）；断签 2 天"想你"剧情
   └→ 金币 → 商城：皮肤/装扮/补签卡/碎片合成（1 期）
   └→ 展示：成就墙/分享卡/周报（家长）
   └→ 回到打开 App
```

## 4.2 三条成长线（互不打架、互相喂料）

| 线 | 产出 | 消费 | 情感锚 |
| --- | --- | --- | --- |
| **成长线** | XP → 等级 → 称号 → 形态进化 | 无（纯荣誉） | 进化仪式、阶段奖杯座 |
| **经济线** | 金币（任务/宝箱/成就） | 皮肤/装扮/补签卡/碎片合成 | 开箱爽感、攒钱目标 |
| **收集线** | 图鉴点亮/金边 + 徽章 + 皮肤收藏 | 无（纯收集） | 集齐闪光、勋章墙 |

## 4.3 图鉴收集系统细化（本期核心工程）

- **载体**：1535 词 → 按「年级-册-单元」60 套（每套 20~30 张），数据可直接从 `words.json` 的 grade/semester/unit 分组。
- **点亮规则**（零冗余存储，延续现设计）：`memory` 的 lv≥3 点亮普通卡、lv≥7 升级金边；**新增"限定卡"**：套系集齐/活动触发的特殊卡面（如 60 套全金边 → 全图鉴限定皮肤）。
- **卡面内容**：正面=单词+音标+朗读按钮+点亮状态框；背面=释义+词性+词根提示/例句+收藏按钮（复用现有数据与 tts；字段缺口按第 11 项兜底策略处理）。
- **套系奖励表**：

| 里程碑 | 奖励 |
| --- | --- |
| 集齐一套（全点亮） | +100 金币 + 该单元纪念徽章 |
| 一套全金边 | 该套专属边框皮肤（展示用） |
| 整册（一学期）全金边 | 限定宠物装扮（如"学期学霸围巾"） |
| 全图鉴 1535 | 终极称号闪卡 + 限定皮肤「图鉴之王」 |
| 每点亮 50 张 | 跃跃学会 1 个新动作（共 ~30 个） |

- **页面**：图鉴页=套卡封面墙（每套一张封面卡：套名+点亮数+进度环）→ 点进翻卡 → 卡背详情；首页 hero 右侧小徽章显示总进度；成就页只保留入口卡（不再放进度条占位）。
- **与训练联动**：今日模式完成时若"离点亮只差 1~2 张"，提示"再学 2 词就能点亮 Unit 3 新卡"——把收集目标变成每日任务的目标（想法 #3）。

## 4.4 情感驱动机制细化（"为了跃跃回来"）

1. **状态机**（维持现有字段扩展）：`hunger / mood / stage / outfit / actions[] / diary[]`。饱食度只降不罚：喂食=学习行为，挨饿只是卖萌文案（已实现，保留）。
2. **想念剧情**：连续 2 天未学，下次打开全屏 2 秒"跃跃举牌：我想你了 🥺"（不做 push；右上角可关）；连续 7 天未学，文案升级为"你还好吗，我们把 Unit 5 捡起来吧"——**分级文案库**（3/7/14/30 天四档）。
3. **进化仪式**：Lv.5 / Lv.12 升级瞬间全屏动画（粒子→剪影→新形态亮相）+ "跃跃进化了！"分享按钮；进化记录存 `pet.history[]`，宠物页可回看。
4. **宠物页**（新增路由 `/pet`）：大图（三个形态×三种心情）、饱食度/心情条、装扮位（试穿）、进化记录、名字修改（现在只能引导期改一次）、互动按钮。
5. **陪伴原则**：互动（戳/摸）不消耗金币不产生 XP（防刷），只解锁表情/动作——严格守住"奖励依附学习"。

## 4.5 数据模型扩展（对 `game` JSON 的增量）

```jsonc
{
  "xp": 520, "coins": 45,
  "daily": { "date": "2026-09-02", "xp": 120, "coins": 30,
             "tasks": { "review": true }, "capNotified": false,   // tasks 已上线
             "bonus": { "firstRound": false } },                   // 首答双倍
  "pet": {
    "name": "跃跃", "hunger": 72, "mood": "happy", "stage": 2,
    "outfit": "none", "currentSkin": "default", "skins": ["default"],
    "actions": ["jump", "wave"],                                   // 图鉴 50 张解锁
    "diary": ["2026-09-03: 消灭了 3 个错词"],                      // 成长日记
    "history": [{ "at": 1756800000000, "stage": 2, "title": "少年狐" }]
  },
  "albumSets": { "7-1-3": { "lit": 21, "gold": 6, "done": false } }, // 套系进度缓存（可推导则免存）
  "frags": { "skin_frag": 2 }, "streakProtect": 1,
  "badges": ["first_study", "streak_7"], "chestLastDate": "2026-09-02"
}
```
> 原则：图鉴点亮状态**不存**（由 memory lv 推导，零冗余）；`albumSets` 仅作展示缓存可清除重建；`daily` 随日期滚动清零。

## 4.6 防沉迷与健康设计（不因游戏化破功）
- 每日 XP/金币软上限（已有）+ 首答双倍计入上限（不额外膨胀）。
- 无付费、无无限抽奖、无全服榜；周榜仅好友/同年级小范围（P2）。
- "学习会话 25 分钟提醒休息"（新增，家长背书）。
- 断签只有温情提醒，无任何惩罚。
